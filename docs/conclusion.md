# Microsoft GraphRAG 代码库实验总结与结论

## 一、核心结论

**本次实验支持将关键词＋向量混合检索作为开发助手的基础检索方案，将 Microsoft GraphRAG 作为需要进一步验证的补充能力。**

- **混合检索在四档预算下的必要源码证据覆盖率均最高。** 4000-token 档为 42.9%，16000-token 档为 77.9%。
- **代码提示词与实体类型配置明显改善了 Local。** 覆盖率从默认版的 5.6%／23.2%，提高到 19.0%／55.4%（分别对应 4000／16000 档），但总覆盖仍未超过混合检索。
- **统一 GraphRAG 最新验证的必要源码证据覆盖率为 43.6%。** 相同评分题集下，低于 BM25 的 64.3%、Basic 的 57.4% 和 hybrid 的 71.0%。

### 2. 代码提示词变更

代码配置组将抽取目标从一般文本中的事物调整为具体代码符号，并增加对名称、关系和来源证据的要求：

| 调整方向 | 代码配置中的具体变化 | 主要影响的表与字段 |
|---|---|---|
| 抽取对象 | 实体类型从 `organization, person, geo, event` 改为 `module, class, function, method, test, constant, external_symbol`；优先识别定义、导入或显式引用的代码符号，避免将作者、普通名词或每个局部变量都作为实体 | `entities.type`，以及哪些实体记录被生成；实体集合变化也影响后续关系端点 |
| 符号名称 | 保留下划线、双下划线、标点和可见作用域；类与方法同时可见时使用 `Class.method`，缺少上下文时不猜所属类、模块前缀、路径或行号；由于下游解析器会转大写，描述中另保留原始大小写拼写 | `entities.title`、`entities.description`，以及 `relationships.source`、`relationships.target`；提示词不能取消解析器的大写转换 |
| 行为描述 | 说明符号在当前片段中是定义还是引用，区分输入类型与返回／存储类型；必要时引用代码表达式或签名，并说明条件和缺失上下文，不仅凭名字推断行为 | 主要写入 `entities.description`；涉及调用条件或关系行为的说明也写入 `relationships.description` |
| 关系语义 | 关系描述明确写出 `DEFINES`、`IMPORTS`、`INHERITS`、`CALLS`、`READS`、`WRITES`、`RETURNS`、`TESTS` 等类型与方向；调用关系注明可见调用方、被调用方及表达式 | `relationships.description`、`relationships.source`、`relationships.target`；本次标准关系表没有新增独立的关系类型字段 |
| 不确定性 | `obj.run()` 只说明语法引用，不自动证明绑定到某个类；无法确定接收者或调用方时写明限制，不断言跨文件目标，也不推断传递调用、全部调用者或完整影响集合 | 限制写入 `entities.description`／`relationships.description`，并影响是否生成具体关系及其端点；没有新增独立的不确定性或置信度字段 |

例如，看到 `HTTPAdapter.__getstate__` 时，新提示词要求保留双下划线；看到 `reserve_stock(items)` 时，要求引用调用表达式并说明可见调用方，而不是仅写“与库存有关”。

### 3. 比较方法与任务

检索比较包含五组：

1. BM25。
2. 关键词＋向量混合检索（hybrid）。
3. Microsoft Basic。
4. Microsoft Local：默认抽取配置。
5. Microsoft Local：代码提示词＋实体类型配置。

20 道检索题覆盖函数／类定位、调用链、有限修改影响检查、无实现问题和运行时未知问题。其中 4 道为 dev、16 道为 test；Q19 无实现且无 gold，不进入召回分母，最终覆盖率按 **15 道可评分 test 题**平均。

### 4. 如何评分

 **必要源码证据覆盖率**：每题预先标注必须检查的源码段，一段至少 80% 的标注行实际进入最终上下文才算命中，再对 15 道可评分 test 题的覆盖率取平均。

例如，一道调用链问题需要检查 5 段源码，最终上下文命中其中 3 段，则该题覆盖率为 **3 ÷ 5 = 60%**。一段证据若有 10 行，至少取回其中 8 行才算命中；重复取回同一段不重复计分。

## 三、检索结果

### 1. 必要源码证据覆盖率

| 方法 | 4000 token | 8000 token | 12000 token | 16000 token |
|---|---:|---:|---:|---:|
| BM25 | 35.3% | 43.7% | 64.3% | 69.3% |
| hybrid | **42.9%** | **56.3%** | **71.0%** | **77.9%** |
| Microsoft Basic | 35.8% | 55.8% | 57.4% | 57.4% |
| Local：默认抽取 | 5.6% | 21.0% | 21.0% | 23.2% |
| Local：代码配置 | 19.0% | 42.2% | 53.8% | 55.4% |

可以支持的判断：

- 本次相同预算上限下，hybrid 的总覆盖表现最好。
- 代码配置 Local 相对默认版分别增加 **13.4、21.2、32.8、32.2 个百分点**。
- 代码配置 Local 在 16000 档相对 hybrid 为 **1 胜、6 平、8 负**，不是所有题都更差，也没有形成总体覆盖优势。

**相同预算上限不等于相同实际源码量。** 16000 档 hybrid 平均实际总量为 15242 token，默认 Local 为 11647，代码配置 Local 为 14403；对应平均源码量分别为 14666、7214、7398 token（按 16 道 test 题平均）。

## 五、统一 GraphRAG 最新运行验证

### 1. 验证设置

本节比较统一 GraphRAG、BM25、Basic 和 hybrid 在 **15 道可评分 test 题**上的必要源码证据覆盖率。题目为 Q01、Q02、Q05、Q07～Q10、Q12～Q18、Q20；均来自原题集，使用相同代码快照和预先标注的必要源码证据。

统一 GraphRAG 复用代码配置图，根据问题文字提前固定路线，不读取参考答案或根据结果改选：

| 路线 | 题目 | 数量 |
|---|---|---:|
| Local | Q01、Q02、Q05、Q20 | 4 |
| DRIFT | Q07～Q10、Q12～Q18 | 11 |
| **合计** | | **15** |

### 2. 必要源码证据覆盖率对比

| 方法 | 必要源码证据覆盖率 |
|---|---:|
| BM25 | 64.3% |
| Microsoft Basic | 57.4% |
| hybrid | **71.0%** |
| 统一 GraphRAG | **43.6%** |

沿用原源码证据标准：每段至少 80% 的标注行被实际读取才算命中，先按题计算覆盖率，再对 15 道题平均。

### 3. 为什么源码证据覆盖率仍只有 43.6%？

| 观察 | 实验中核实的情况 | 对源码覆盖的影响 |
|---|---|---|
| 实体与实现原文的来源关联不完整 | Q01 的容器实现已经入库，相关实体和方法名也能出现，但实际 Sources 没有取回 `structures.py` 的容器实现；最新逐题源码覆盖仍为 0% | 找到名称和描述，不等于沿关联找到实现源码 |
| DRIFT 的追问没有补齐入口证据 | Q07 实际执行的子查询关注代理／TLS、发送实现和参数，入口 wrapper 的追问没有执行，`api.py` 入口未取回；其源码覆盖为 60% | 有限的局部查询可以花在旁支，多次搜索不保证补全所需链条 |

### 4. 结论

**统一 GraphRAG 的最新源码覆盖率为 43.6%，仍低于三个基础检索方法。** BM25、Basic 和 hybrid 分别高出 20.7、13.8、27.4 个百分点。

## 六、统一 GraphRAG 必要要点完成分

本节单独评价最终答案是否完成题目要求，按原 **16 道 test 题**平均。相比源码覆盖评分，额外纳入无实现题 Q19，其路线为 Local；四种方法在这 16 道题上均已生成最终回答。

### 1. 评分方式

每题的必要要点提前冻结，各要点按 **1（完整覆盖）／0.5（部分覆盖）／0（未覆盖）**评分，先在题内取平均，再对 16 道题取平均。

例如，一题有四个必要要点，得分为 1、1、0.5、0，该题完成分为 `(1 + 1 + 0.5 + 0) ÷ 4 = 62.5%`。Q19 虽然没有可检索的实现源码，但可以评价答案是否正确说明“该快照没有该实现”，因此可以在这里评分。

### 2. 最新结果

| 方法 | 回答必要要点完成分 |
|---|---:|
| BM25 | 70.4% |
| Microsoft Basic | **79.1%** |
| hybrid | 78.1% |
| 统一 GraphRAG | **72.8%** |

**72.8% 表示必要要点的平均完成程度，不是完全答对的题目比例，也不是全文准确率。** 

### 3. 结论

统一 GraphRAG 的回答完成分高于 BM25，低于 Basic 和 hybrid。能从图描述或社区报告回答部分要点，不等于已经取回对应实现源码，因此本节结果与上一节的源码覆盖率分开呈现。
