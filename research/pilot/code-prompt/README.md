# 代码专用抽取提示词：隔离验证

这是在已知默认版失败之后追加的一个受控变体，检验“让模型按代码符号抽取，能否改善 Local 实际交回的源码证据”。它不是新的盲测，也不预设提示词就是此前差距的主要原因。

## 执行前固定了什么

[计划](plan.json)、[完整提示词](extract_graph.txt)、[运行入口](../code_prompt_experiment.py)和[预检材料](../results/code-prompt/preflight.json)先保存在提交 `7e0c04fdd577ed346e12e4c5170e0106f224d09e`。首个真实请求开始于 **2026-10-13 13:12:59 UTC**。旧版图、问题、gold、评分协议及旧结果的 SHA-256 也在预检中固定。

新增的不是 AST 图。Microsoft 标准抽取算法仍由模型阅读114个原文块，只把抽取提示词和实体类型一起换成面向代码的配置：模块、类、函数、方法、测试、常量及外部／未解析符号。提示词要求保留可见作用域和下划线，区分输入与存储类型，给关系写出种类、方向、代码表达式和动态绑定的不确定性。没有加入题目、gold、已知失败符号或原文中未给出的路径／行号。

描述合并、社区报告、一次补抽、解析器、聚类与 Local 检索参数均保留原样。源码、20道问题、4k／8k／12k／16k预算及评分方法不变。只增加原始图快照输出，便于审计，不改变生成算法。

新运行使用独立目录与缓存，**不导入旧生成响应**；只复用114份完全相同的源码向量和20份问题向量。图描述与社区报告重新生成并向量化。旧四组的320份检索结果不重跑、不覆盖；新变体计划形成80份上下文。两项功能生成不在本轮范围内。

## 预算与停止边界

初始计划每次仅一个请求，无自动重试。生成最多1200次、共同计量输入800万token、单请求16000输入token、请求输出上限2048、60秒请求时限和3小时总时限。代理可能忽略请求输出上限；完整有效响应保留真实用量，不截断后冒充遵守上限。后续明确授权的有限重试与110起120秒时限见文末，原计划与失败不回写。

OpenAI embedding 沿用累计 **$1** 上限，先计入此前206,333个token（按每百万$0.13估算为$0.02682329），不重置预算。只为新图描述产生新embedding请求；源码与问题向量复用。Fullstar生成费用不估算，报告实际次数、token和时间。模型仍在远端运行，Mac mini负责编排；没有本地模型权重推理，也没有通过浏览器执行。

## 评分及独立复核

主要结果仍是15道可评分测试题的必要源码证据覆盖；开发题和全题结果单列。Q19无实现负例不进入召回分母，Q20不能确定应用运行时目标。MRR、Recall@5/10使用实际 Sources 顺序，不是假定模型阅读后的回答正确率。

图质量不按“实体更多”直接判好。对两张固定图分别按 `SHA256("20261012:表名:ID")` 排序，选20个实体和20条关系，回查其实际关联源码，记录支持、部分支持／含糊、无支持及符号／方向／动态绑定问题。这是小规模AI独立审阅，不是人类标注或全图准确率。另追踪此前已指出的Q01／Q07／Q13／G02错误链；这些个案不另行改分。

新 Local 若改善，最多说明**这组提示词＋实体类型配置**与改善同时出现。模型采样、服务随时间变化和独立建图的随机性未用重复运行隔离，不能仅凭一次前后比较证明提示词是主要原因。报告提示词仍为默认版；代码实体类型不会自动补齐切块缺失的作用域、稳定符号身份、动态调用目标或完整影响集合。

## 启动后收到的格式复核意见

运行边界已在启动前独立检查。更细的提示词复核在首个真实调用后指出：固定上游把初抽和补抽字符串直接相连，不插入分隔符。初抽结束标记若紧接补抽第一条记录，该记录可能无法被解析。新提示词要求正确的结束标记，但没有额外要求补抽以 `##` 开头；旧默认输出也可能受此影响。

因此没有中途改提示词、解析器或重建已完成的块。后续将对**新旧两次既有响应**同时比较“分开解析”与“官方直接拼接解析”的记录差异，保留真实结果；这个诊断不是修复后的图或检索结果。它限制本轮对最优代码提示词的推断，不能事后隐去。

初始阶段不调用新的 Global。待新图报告数量和 Local 结果明确后，再说明原六题 Global 是否有必要验证变化后的报告错误；不借此新增题目或功能生成。

## 复算与重新执行

只复核已公开的冻结文件、中断历史和旧图抽样，不需要模型、网络或凭据：

```bash
python3 research/pilot/verify_code_prompt.py
```

索引完成后的 Local 验证入口为 `evaluate_code_prompt.py`：`export` 导出准许公开的账本与表，`retrieve` 在本机读取图和134份既有向量缓存，`score` 生成比较，`check` 从公开上下文重算。`retrieve` 不读取 gold；`score/check` 不实例化提供商适配器。`--tokens` 精确重数需要固定 tokenizer；不带它的评分验证使用标准库。`diagnose_code_prompt.py parse` 对已有响应作拼接诊断，`sample` 生成固定抽样。未完成索引时，这些产物尚不存在，不能把入口已写好算成实验已完成。

重新调用模型不是离线复算。它需要先按[原运行附录](../full-run.md)准备同版微软依赖、固定语料及已经核验的旧图和源码／问题向量，另备新的工作副本和输出目录，保留发布版结果后才运行 `code_prompt_experiment.py prepare`、`index`。入口对已有运行／输出拒绝覆盖；没有“一条命令删掉旧结果再跑”的捷径。远端输出不能保证逐字重现，预算与原失败记录均需单独保留。
