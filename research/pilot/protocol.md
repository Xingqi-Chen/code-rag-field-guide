# 冻结协议：Requests 代码证据试点 v1

这是模型执行前的协议，不是效果报告。原始问题、证据、输入文件、配置模板与本协议由 [freeze.json](freeze.json) 哈希冻结。模型/provider/真实维度/运行预算仍待确认；执行前另存 run manifest，不改题集。若必须更改题意或评分，升版并重跑全部方法，不按已见结果挑题。

## 题目及污染边界

[questions.json](questions.json) 共 20 个英文实际输入：定位 6、调用追踪 6、有限影响检查 6、找不到符号 1、运行时目标未知 1。`Q03/Q04/Q06/Q11` 为 dev，剩余 16 为 test。dev 只用于接口、格式和评分器机械验收，不优化提示词、检索参数或实体类型。分题不等于跨仓库／跨主题独立：同一项目、相近机制会共享知识，不能宣称独立泛化或行业代表性。

[features.json](features.json) 另有两个探索性 test feature，每个都从相同**修改前** commit 开始。它们是根据源码提出的原创任务，并非 upstream 已承诺功能，也不是官方 SWE-bench 题目。验收测试在研究目录，原版索引仅接受 [corpus.json](corpus.json) 路径白名单；绝不混入 feature 测试、gold、未来补丁、Git 历史或本研究文档。不给编辑模型看验收文件；模型可以写自己的测试，但评分仍用未修改的冻结验收器。当前库是公开材料，不保证模型训练未见过源码；此前本研究旧版本用过相同 Requests 快照，也不是完全未知语料。旧题／结果不作为本轮调参依据。

## 输入、方法与预算

共享 41 个源码／测试／文档／配置文件；空正文不索引。统一为不超过 1200 `o200k_base` token 的整行块，重叠最多 100 token；微软再次切块设 1200/0。此输入适配旨在可核对行号，不能称完全原样默认切分。无 AST 分块、无定制实体类型／抽取提示词。微软输出必须与输入逐字、逐 ID 映射验收，重复正文或静默截断立即停下。

| 对照 | 固定设定与作用 |
| --- | --- |
| 精确文本／符号参考 | 固定 snapshot 上 `rg -n -F` 与 Python AST 定义列表，报告命中的路径／行号；只是便宜诊断，不冒充作用域完整的引用分析器或 LSP |
| BM25 | 保留完整标识符并拆 snake/camel 片段，k1=1.5、b=0.75；[本地实现](baselines.py)不读 gold |
| 普通 hybrid | 同一 BM25 与真实同模型向量 cosine 各取前 20，RRF 常数60、等权；稳定以输入顺序打破平分；不把 TF-IDF 当 embedding |
| Microsoft Basic | 固定 v3.3.0 内部上下文 builder，k=10；保留它实际输出顺序，不把自写 dense 排序叫微软 Basic |
| Microsoft Local | 同版本 Standard 索引，默认抽取类型和 prompts；实体10、关系10、source0.5/community0.15；社区层级选实际存在的最大且不超过2的层；无此层返回空，记录所用层，不能看效果后选择 |

所有向量部分必须使用同一个明确模型/版本、维度与输入规范；共用源码块向量和22个查询向量缓存，分别记逻辑调用和实际请求。最终共同 token 计数器为 `o200k_base`，服务计费另计。共同上限 **4,000 token 主比较、12,000 token 次比较**；源码、实体、关系、社区报告、表头及模型可见来源标识都计入。预算由 runner 覆盖模板默认12000；若追加来源映射超预算，按统一预定尾部条目裁剪规则重新计算并记录，不能偷偷多给微软或基线窗口。索引成本、查询计算和最后上下文预算是三个不同量。

未来 runner 要保存官方原始上下文，以及适配后实际交给下游的上下文，分别核算；不能只保存排名列表。本文没有完成该 runner 的微软导入/表映射集成。模型选择后先做兼容性检查，再补齐运行集成，之后才能报告效果。

首轮不做 reranker、agentic、多模型组合、DRIFT、代码提示词或外接 AST 图；这些会另加计算／改系统身份。固定相同最终预算与更小/更大预算曲线，只能检验“是不是多给上下文”；不能据此识别所有图因果贡献。没有等预算有效消融时，不宣称收益专门来自图。更新／删除／重命名实验也单列后续，首轮仅固定静态快照。

## 评分单位及复核

[gold.json](gold.json) 和 [feature-gold.json](feature-gold.json) 中每个 evidence 是**固定路径 + 闭区间行号 + 片段哈希**，对应一个需要检查的事实。仅取回父文件名、关系描述或声称引用某块，不能等价于真正取回支持它的原文。须通过 provenance 把实际 Sources 内容还原到源码行；没有来源的材料单列。

- 主指标为必要证据覆盖率：同题实际上下文中去重后的源码行覆盖该 evidence 至少80%才算命中；按题平均，另报逐类。严格100%覆盖作附表，不更换主阈值。空 gold 的 Q19 无 recall/MRR 分母，单列找不到符号表现；Q20 有证据但目标必须保持未知。
- Recall@5/@10 与 MRR 的排名单位是**实际展示的源码块**。Recall@k为前k个实际源码块合并、去重源码行后，命中的必要evidence数除以该题gold evidence数；无gold题排除。MRR 为第一个单块覆盖任一 gold evidence 至少80%的倒数，未命中时为0；不把实体/社区行数当源码块rank。所有方法还报实际上下文证据覆盖，以防表排序与最终窗口不同。nDCG暂不加，因为没有可靠的逐块多级完整相关性标注。
- 影响 gold 是有限必要检查集，**不是完整必须改动文件集合**。未列入 gold 的材料记“未判定”，不能全部叫噪声。两位审阅者在隐去方法名后核对新增有效证据、无关材料和错误关系；保留原冻结分数并单列共同扩展的判定，不静默改 gold。噪声率只对人工完成判定的内容报告。
- 调用方向／类型和回答中的符号定位正确性需额外结构化回答或人工判读。当前只准备纯检索：不从证据覆盖直接推算边精确率、实际答案正确率。后续回答阶段要记录限定分支、动态未知、错误位置和有效替代路径；相关但非调用关系不得算 verified call。
- 小样本不做显著性筛题。公开逐题原始context、映射、token、失败及聚合代码后才发布结果；报告 paired 差值与全部失败案例，不能只挑赢家。当前没有任何检索结果。

## 下游 feature 独立记账

F01 增加大小写无关字典合并运算；F02 增加 Session 默认超时，同时保留显式 `None`。每个方法一次生成尝试、相同编辑模型/版本/系统提示/4,000-token初始证据预算，建议先禁额外源码搜索；若需要搜索，另做所有组同权限条件并记录全部额外上下文。编辑模型与操作/输出预算在后续 run manifest 中确认，未选定前不执行。

同一方法的两项 feature 分开使用干净副本，不堆叠补丁。先审查补丁范围，再将模型改动放入 `.cache/pilot/candidates/` 独立测试副本，使用 `run_tests.py --candidate`；不得运行模型新增安装/网络脚本。此测试 runner 的 TCP/DNS mock 只是对已审代码的额外保护，不是任意补丁的安全沙箱。应用固定验收测试，随后固定使用原快照中的59项回归（仅被测src来自candidate，不接受候选改写验收测试）与人工核对（文档、约束、异常和未测场景）。新验收通过数、回归结果、人工需求正确性分别报告；2题不构成可靠成功率估计，不与 SWE-bench 官方分数相比。没有 gold patch，不以改了历史PR同样文件作为真值。

## 资源、失败与审批边界

现阶段脚本只下载固定公开源码／小型 tokenizer、做静态整理和断网测试。微软包未安装；配置只做静态字段/语法核查。当前模型调用为0，不能报告索引速度、内存、费用或效果。后续记录每阶段墙钟、峰值RSS、磁盘、CPU/内存、模型input/output、重试、失败、缓存、provider usage与出处丢失。

模型/API/金额预算未选定。最小下一阶段是单独获准的8块兼容性抽样，校验completion格式、community JSON、embedding维度与截断、共用向量、完整原文映射。请求/ token 估算见 [准备说明](README.md)；执行前必须把服务端限额和本地计数停止器落实。只有8块通过且用户确认完整索引预算，才做114块正式索引。基础设施错误允许原参数重试并完整记账；预算、来源、模型身份或服务格式不明确即停，不为凑结果改题。
