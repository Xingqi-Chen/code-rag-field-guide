# 研究计划：Microsoft GraphRAG 能否做好开发助手的代码索引

日期：2026-10-12。按本轮聚焦要求修订：目标是评估 Microsoft GraphRAG 能否作为开发助手的代码索引／上下文检索层，帮助准确定位、理解和修改代码。保持适合团队 10–15 分钟分享的中文图文说明。固定研究对象仍为 `microsoft/graphrag` v3.3.0；其他图系统不能替代它的证据。

## 先回答四个开发任务

1. **精确找函数与符号：** 同名、重载能否区分，是否能准确返回路径、行号和代码版本？
2. **追真实调用与依赖：** 边有没有方向和依据，能否跨文件解析，动态派发和未知目标如何表示？
3. **分析修改影响：** 能否找全上游调用者、接口／实现、配置和相关测试，同时控制遗漏与误报？
4. **辅助实现 feature：** 能否交给下游编辑工具足够准确的跨文件上下文、规范和测试？检索质量与最终改动正确性分别评价。

整体架构总结和社区导读只作为机制背景或辅助收益假设，不用文本总结质量替代代码索引准确性。

## 研究顺序

1. 核查官方文档与固定源码的数据模型、来源定位、符号身份、关系语义、查询选择和更新新鲜度。区分默认流程、提示词定制、外接程序分析图；未找到某能力不等于证明所有扩展都不可能。
2. 补查上述四类任务的直接微软评测，记录检索词和排除项，先确认实现身份再看分数。传统代码索引／LSP 只用于解释相关对照，明确其语言覆盖和动态调用边界。
3. 汇总证据后再判断实验必要性。证据缺口不能用旧自制图实验或教学图填补。本轮允许无付费的源码静态检查，不启动模型推理或付费调用。
4. 按四任务重写主文，用一个小 feature 场景说明函数、调用者、配置、测试和干扰材料；配图明确为人工示意。细节与必要验证方案留在附录。
5. 独立复核事实、引用与非技术读者可读性；完成图片、链接、秘密与发布检查，正常 commit/push。

## 什么才算直接代码证据

候选必须同时能确认研究的是代码任务，以及实际采用 Microsoft 实现或明确可识别的实现／改动。优先检查：版本与配置、语言和规模、问题类型、基线和预算、判分方式、数值与成本、公开复现材料。只有演示或作者感受的项目单独列出，不能升级为受控评测。

没有找到满足条件的材料时，写“在本轮范围内未检索到足够直接证据”，不写“没有人研究”。其他代码图、通用文本评测和营销说明记录为背景或排除项，不能替代核心证据。
