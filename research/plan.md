# 本轮研究计划：Microsoft GraphRAG 与代码库理解

日期：2026-10-12。目标是做一份适合团队 10–15 分钟分享的中文说明，帮助决定是否值得试点。研究对象是 Microsoft 发布的 `microsoft/graphrag`；泛称“图 RAG”的其他系统不能替代它的证据。

## 先回答三个问题

1. **局部代码问答：** 能否准确解释一个函数、参数或异常条件，并给出对应源代码？
2. **跨文件流程：** 能否串起入口、调用、配置和后续行为，且不编造不存在的关系？
3. **整体架构理解：** 能否把模块职责、共同主题和协作方式讲清楚，帮助新人建立概览？

## 研究顺序

1. 独立核查官方论文、文档和固定版本源码。说明输入、切分、实体关系、社区、社区报告和查询模式；将代码中可确认的事实与效果推断分开。
2. 独立寻找直接代码评测。记录检索词和重要排除项，先确认评的究竟是不是 Microsoft GraphRAG，再看结果。
3. 汇总证据后再判断实验必要性。证据缺口不能用旧自制图实验或教学图填补。本轮允许无付费的源码静态检查，不启动模型推理或付费调用。
4. 写通俗主文与原创配图，把详细证据、版本和后续实验方案放在研究附录。
5. 独立复核事实、引用与非技术读者可读性；完成图片、链接、秘密与发布检查，正常 commit/push。

## 什么才算直接代码证据

候选必须同时能确认研究的是代码任务，以及实际采用 Microsoft 实现或明确可识别的实现／改动。优先检查：版本与配置、语言和规模、问题类型、基线和预算、判分方式、数值与成本、公开复现材料。只有演示或作者感受的项目单独列出，不能升级为受控评测。

没有找到满足条件的材料时，写“在本轮范围内未检索到足够直接证据”，不写“没有人研究”。其他代码图、通用文本评测和营销说明记录为背景或排除项，不能替代核心证据。

## 实验与发布边界

- 使用公开文献、官方源码和原创小例子，不含公司代码或私人资料。
- 不读取、复用任何其他项目的模型凭据或调用授权，不开启付费模型调用。
- 若需要真正运行 Microsoft GraphRAG，先交付模型／提供方、数据传输、调用规模、费用估计及本地路线的方案，等待另行决定。未实测就明确写未实测，不阻塞文献研究版发布。
- 旧代码结构图实验从当前阅读入口移出；原提交和数据仍可经正常 Git 历史追溯。不改写历史，不 force push。
