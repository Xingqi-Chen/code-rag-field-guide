## 怎样复核源码

只用 Python 标准库。已有完整缓存时不联网：

```bash
python3 scripts/check_source.py
```

新 clone 需要先下载清单指定的官方 raw 文件：

```bash
python3 scripts/check_source.py --fetch
```

`--fetch` 仅把缺失文件下载到 `.cache/`，按固定 commit URL 和哈希核对，不解压、不导入、不运行第三方代码，也不读模型凭据。它校验**引用文件与清单一致**，不会自动证明报告的语义解释；解释还需阅读源码与独立审阅。本轮结果为 46 文件全部通过，见[真实运行记录](../logs/source-check.log)。发行信息和归档哈希也记在清单中；新 clone 只取引用文件，无需下载整份源码归档。

## 怎样检查发布内容与图

```bash
python3 -m unittest discover -s tests
python3 scripts/validate.py
```

检查相对 Markdown 链接和行号／标题锚点、四对 PNG/SVG 的格式与尺寸、PNG 元数据和 CRC、SVG 可访问性与无主动内容、文件大小、路径与常见密钥模式，以及旧实验目录没有混回当前版本。这些检查不能证明所有外链永远可访问，也不能保证识别所有秘密。

配图命令、依赖和字体要求见[配图说明](../docs/figures/README.md)。实际用同一份几何定义输出 SVG 和 2 倍分辨率 PNG；人工逐张看完整 PNG 和 390 像素宽预览，检查字、框、箭头和阅读顺序。正文使用 PNG，因此不依赖阅读器提供相同中文字体。SVG 做源结构校验；本轮没有声称在浏览器中完成 SVG 的视觉渲染检查。

轻量测试和发布内容检查的实际输出见[运行记录](../logs/publication-checks.log)。检查器曾把代码示例中的 `handlers[name](order)` 误认成链接；已让链接检查跳过代码片段，并增加对应回归测试。

## 发布方式

使用项目专用 Git 作者名，正常新增 commit 和 push，不覆盖历史；只更新本研究仓库。发布后核对 public 可见性、远端 HEAD、该 SHA 对应的 CI，以及匿名可读的 README、报告和图像。最终 SHA 与 CI 链接随交付给出，避免在同一提交里写入自引用的提交哈希。
