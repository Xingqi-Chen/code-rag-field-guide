# 是否需要实验：一份尚未执行的试点方案

日期：2026-10-12。**本文件是决策材料，不是实验报告，也不是模型调用授权。** 本轮只做静态源码和文献核查，没有运行 Microsoft GraphRAG 索引、生成答案或调用 embedding 服务。

## 为什么仍值得考虑，又为什么可以暂缓

[直接证据核查](direct-evidence.md)没有找到足以替代本团队评测的微软代码理解结果。社区报告可能帮助概览，但代码精确事实、跨文件流程和成本是否改善，都仍是待测问题。如果团队现在只需要理解原理，这份报告已经可以使用；如果准备采购、接入或向同事承诺收益，就需要目标场景上的比较。

不建议先跑大库。先做接口兼容性检查，再做一个范围明确的小比较；兼容性失败也应记录，不能换成自制代码图后继续叫微软实验。

## 两条路线，都需要另行决定后才执行

| 项目 | Mac mini 本地路线 | 云端参照路线 |

现有机器是 Apple M4、10 核 CPU、16 GiB 内存。它适合考虑小模型试点，不能据硬件规格保证能同时容纳模型、向量库和整条索引流程，也不能预报速度。建议先用原创小店例子的几个文本段检查 JSON 格式、实体记录、社区报告及向量维度；兼容性通过后才申请进入完整比较。[Qwen 官方模型卡（Apache-2.0）](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct)、[MiniLM 官方模型卡](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)。模型卡不是对所有第三方量化文件的来源保证。

固定微软源码支持配置提供方和 API 基址，但“能配置”不等于任意本地模型可靠兼容。结构化输出、批量向量、截断和重试都需要验证。两条路线采用不同模型时应分别报告，不把差异全部归给 GraphRAG。细节见[接口核查](implementation.md)。

MiniLM 候选的最大输入只有 256 word pieces，不能直接把微软默认 1200 token 的文本段交给它后忽略截断。若选它，应先在独立小样例上确定共同分块方案和 token 计量方式，冻结后用于全部方法，并公开相对微软默认配置的改动；也可以另选输入容量合适的小型模型。此决定必须早于正式题集运行。

## 最小比较怎么设计

以下是**拟议范围**，尚未生成、冻结或评分题集：

1. 选一个许可明确的公开 Python 小仓库，固定 commit 和输入清单；例如 Requests。先设最多 50,000 个输入 token 的试点上限，实际纳入文件和许可在开始前逐项登记。不能看到成绩后再删难文件。第一轮只读代码；如果另做代码加文档，应作为独立输入条件，让所有对照获得相同材料。
2. 冻结 18 题：局部、跨文件、整体架构各 6 题；其中至少 3 题是材料不足或前提错误的题。每题先写源码依据、必须提及的事实、不得推出的结论，再运行任何方法。人工检查者不能根据某个方法的输出改金标准。
3. 比较强关键词加真实向量的 hybrid、微软 Basic、微软图查询路线三组。图路线的 Local／Global 分配在看答案前按题型写入协议；不得看表现选最好的模式。DRIFT、提示词调优和 AST 适配留到后续消融，不在初轮堆入。
4. 使用相同生成模型、embedding 模型和输入文本清单；hybrid 与 Basic 共用可行的分块边界，并记录微软图索引的转换。初始拟定最终回答上下文 8,000 token、输出上限 800 token。Global 的中间 map 调用另外记录并限额，不能把“最终窗口相同”说成“总计算预算相同”。
5. 各方法每题生成两次，即至少 108 次最终回答生成；模型可用的 seed、温度、所有配置写入运行清单，不能保证服务端完全确定性。每次保留实际检索材料、模型输出、token、耗时、调用与重试记录。重复结果只描述查询生成波动，不挑好的一次；如果只建一次图，就没有测量索引随机性。
6. 隐去方法名，请同事按预先量表检查事实、流程缺漏、引用支持和无依据的推断。分别报告三类题与负例表现、检索证据覆盖、索引和增量更新成本、失败个案；同时记录评审者分歧。18 题只能支持试点判断，不能代表行业，也不宜追求显著性。

如果整个输入本来就能放进模型窗口，可另加“完整输入加问题”的长上下文参照；必须把额外读取量和费用单列。若无法让两种索引使用相同粒度，应明示这一混杂因素。对比模型、输入、预算或提示词不一致时，不做因果归因。

冻结协议还必须明确：首轮采用微软默认实体类型和提示词，还是预先设计的代码适配类型与提示词。二者是不同实验条件；若选适配版，应逐项公开改动，并避免把成绩称为默认配置的表现。不能读完正式题集答案后再改提示词。

## 云端费用算例，不是运行账单

2026-10-12 访问的官方标准价格：GPT-4.1 每百万输入 token **$2**、输出 **$8**；text-embedding-3-large 每百万输入 token **$0.13**。此处不假设缓存折扣或 Batch 折扣，不含税、汇率及其他服务费。[GPT-4.1 价格与快照](https://developers.openai.com/api/docs/models/gpt-4.1)、[embedding 价格](https://developers.openai.com/api/docs/models/text-embedding-3-large)。执行前应重新核价。

| 规划变量（整轮累计） | 低算例 | 高算例 |
| --- | ---: | ---: |
| 生成模型输入 token | 500,000 | 2,000,000 |
| 生成模型输出 token | 50,000 | 200,000 |
| embedding 输入 token | 100,000 | 500,000 |
| 计算所得 API 费用 | **$1.413** | **$5.665** |

公式：`费用 = 输入/1e6 × 2 + 输出/1e6 × 8 + embedding输入/1e6 × 0.13`。粗略规划约 200–600 次生成请求（包含 108 次最终回答、索引抽取/总结和查询中间步骤），向量服务约 10–50 次批量请求。这些数量是用于做决定的假设，**不是实测上界或服务保证**：社区数、实体数、Global 批次、批量大小、重试和提取轮数都会改变它们；请求数本身也不能直接换算费用。

如选择云端，可提议 **$10 的停止阈值**：每次请求前预留其最大输出及输入费用，达到阈值就停止并报告未完成。另设生成请求总数上限；仍须处理并发请求和失败请求是否计费的情况。未经实际实现与验证，不能把文档里的阈值称为已经生效的保护。

## 开始前需要确定的事项

选择本地或云端、可用时间与资源上限、语料和题集负责人，以及是否愿意安排人工盲评。云端还需明确授权提供方、数据传输和费用上限；不因账户中可能已有凭据而视为获准。确认之后，先提交冻结协议再执行。**以上待决不阻塞本轮文献研究公开发布。**
